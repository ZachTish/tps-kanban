# TPS Kanban 0.1.1

TPS Kanban `0.1.1` is a backward-compatible rendering-efficiency release. It removes one duplicated synthesized-task build from every board render without changing task discovery, lane synthesis, ordering, cards, settings, or persisted board state.

## Changes

- `renderAsync()` builds task render items once from the original populated groups.
- Empty task-only lane groups are still synthesized from that result.
- Parent relationships and note-card presentation indexes are still rebuilt from the augmented group list.
- The verified task map is reused because the added synthetic groups contain no note entries and therefore cannot change source files or task-to-lane mapping.

## Performance evidence

- A vault-wide task board now performs one `buildTaskRenderItemsByLane()` traversal per render instead of two.
- For task filters that scan every Markdown file, this cuts that stage's file visits from approximately `2N` to `N`.
- The runtime change deletes the second build call and adds no cache, persisted state, timer, or fallback.

## Validation

- `npm test`: all 62 declared checks passed.
  - Three shared TPS contract tests.
  - Five Base-filter composition tests.
  - Fifty Kanban utility/rendering tests.
  - Four routed-settings contracts.
  - TypeScript and the production bundle passed.
- The focused regression compares the reused task map with the former post-synthesis recomputation oracle and verifies identical lane keys, task counts, task identity, and task order.
- A separate final `npm run build` passed and deployed only to `.obsidian/plugins/tps-kanban` in the isolated test vault.
- Obsidian 1.12.7 was reloaded with **Reload app without saving**; the loaded plugin settings list included TPS Kanban (Dev).
- Runtime-owned `data.json` was absent before and after validation.
- Production was not accessed or modified.

## Compatibility and limitations

- Minimum supported Obsidian version remains `1.10.0`.
- No settings or data migration is required.
- All existing task-filter, source-target, synthetic-lane, manual-order, and completed-task behavior remains unchanged.
- The release does not introduce caching; other documented full-vault task scans still occur once when the active filter requires them.
