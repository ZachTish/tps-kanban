# TPS Kanban 0.1.2

TPS Kanban `0.1.2` is a backward-compatible render-efficiency patch. It removes parent and note-lane indexes that were built before task-only lane synthesis and then unconditionally discarded.

## Changes

- Task render items are still built from the original populated groups.
- Empty task-only lanes are still synthesized from that task result.
- Parent relationships and note-lane trees are now built once, after the final group collection is known.
- Lane order, nesting, task identity and order, card output, settings, and persisted board state are unchanged.

## Performance evidence

- Parent-index construction falls from two calls to one per affected render.
- Note-lane tree construction falls from two calls to one when note entries are enabled.
- The runtime patch is net four fewer source lines and adds no cache, state, fallback, timer, or background work.

## Validation

- `npm test`: all 62 declared checks passed.
  - Three shared TPS contract tests.
  - Five Base-filter composition tests.
  - Fifty Kanban utility/rendering tests.
  - Four routed-settings contracts.
- Focused coverage verifies the same final task, parent, and note-lane indexes and asserts one final build of each index.
- A separate final `npm run build` passed and deployed only to `.obsidian/plugins/tps-kanban` in the isolated test vault.
- Obsidian 1.12.7 was reloaded with **Reload app without saving**; `Plugin QA.base` rendered the expected `todo` and `working` task cards and empty ungrouped lane in the Kanban view.
- Runtime-owned `data.json` was absent before and after validation.
- Production was not accessed or modified.

## Compatibility and limitations

- Minimum supported Obsidian version remains `1.10.0`.
- No settings or data migration is required.
- The release does not add caching; required task discovery and final render indexes are still built once.
