# TPS Kanban 0.1.3

TPS Kanban `0.1.3` is a backward-compatible task-preview reliability and performance patch. It replaces path-only loading flags and unowned bullet reads with one identity-checked ownership contract for asynchronous vault reads.

## Changes

- Task and bullet reads capture an immutable source path and may commit only while they still own that path and Obsidian still resolves it to the same `TFile`.
- A modify can immediately start a fresh read; an older success or failure cannot overwrite the newer cache.
- Rename, delete/recreate, same-path file replacement, folder rename/delete, and view unload invalidate affected reads and caches.
- Delayed renders are gated after unload, so they cannot reopen task reads after teardown.
- Concurrent bullet-preview requests for the same file share one pending read.
- Bullet read/parse failures are caught, logged with the source path, and left uncached so a later render can retry.
- Task parsing, Base filters, ordering, completion visibility, preview limits, overflow counts, settings, commands, and stored data contracts are unchanged.

## Before/after evidence

The focused regression was first run against released `0.1.2`:

- A modify, rename, delete/recreate, or same-path replacement could not start a second task read while the first path remained marked as loading.
- An older completion could repopulate stale path state because cache writes used the mutable `file.path`.
- One hundred pending bullet-preview requests issued 100 `cachedRead` calls.
- View teardown had no all-cache/read invalidation method.

With `0.1.3`:

- All seven ownership, stale-success, stale-failure, retry, replacement, and teardown scenarios pass.
- One hundred pending bullet-preview requests issue exactly one `cachedRead`, a 99% reduction in vault-read work for that burst.
- A stale finalizer cannot remove a newer owner or trigger a false repaint.
- Task reads still repaint once when the current task batch drains; successful bullet reads still repaint when their cache commits.

## Compatibility and limitations

- Minimum supported Obsidian version remains `1.10.0`.
- No settings or data migration is required.
- Superseded `cachedRead` Promises cannot be cancelled by Obsidian; they may finish physically, but ownership checks prevent stale parsing, cache writes, and repaints.
- Normal task-read failure keeps the released empty-cache behavior. Bullet failure remains uncached and retries on a later request.
