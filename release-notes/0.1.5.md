# TPS Kanban 0.1.5

TPS Kanban `0.1.5` is a backward-compatible task-cache performance and reliability patch. It removes the second full Markdown parser pass from every cold task-source read while preserving the complete released feature set.

## Changes

- Each task source is parsed once into the complete ordered task collection.
- The bounded open-task card preview is derived in one pass over that collection instead of reparsing the Markdown.
- Completed-state filtering resolves checkbox status only when filtering requires it; the all-task parse no longer performs an unused status mapping.
- GCM task extraction remains an optional enrichment and overflow source. Local parsed task identity, text, hierarchy, and inline fields retain their existing precedence.
- Task ordering, parent-line relationships, custom checkbox mappings, preview limits, overflow behavior, task-lane data, stale-read ownership, failure behavior, repaint batching, settings, commands, and stored data are unchanged.

## Before/after evidence

The release comparator compiles and executes the real `KanbanView.loadOpenTasksForFile` implementation from exact public `0.1.4` and the versioned candidate.

- Seventeen parity scenarios passed across all supported task states, nested hierarchy, inline fields, default and custom completion mappings, negative/fractional/finite/infinite/NaN limits, GCM service and legacy routes, duplicate and invalid GCM lines, local-vs-GCM field precedence, numeric/negative/undefined/NaN overflow, and extractor failure.
- The parity-output SHA-256 digest was `ba33249a9f7a74fb020766e18f1d0fcf34e2c3c3da4742c8a1d013e0385a2da6`.
- Across 500 cold loads of a 20,000-line task source:
  - Parser calls: `1,000` in `0.1.4` to `500` in `0.1.5` (50% reduction).
  - Full-content line visits: `20,000,000` to `10,000,000` (50% reduction).
  - Vault reads: `500` to `500`.
  - Settled-batch repaints: `500` to `500`.
  - Median per ten-load sample: `896.2 ms` to `625.4 ms` (30.2% faster).
  - p95 per ten-load sample: `926.2 ms` to `644.1 ms` (30.5% faster).

The benchmark hard-fails unless exact `0.1.4` performs two parser passes per cold read, the candidate performs one, line visits are exactly halved, reads and repaints are unchanged, and both median and p95 improve.

- Production was not accessed or modified.

## Compatibility and limitations

- Minimum supported Obsidian version remains `1.10.0`.
- No settings or data migration is required.
- No command, setting, view mode, creation path, task mutation path, or integration contract was removed.
- GCM remains optional. Its supported service route and the native standalone behavior are unchanged.
- The whole-vault Base-note recovery path is intentionally unchanged because it can recover matching cards absent from native groups; removing it without a replacement contract could hide released content.
