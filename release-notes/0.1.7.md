# TPS Kanban 0.1.7

TPS Kanban `0.1.7` is a backward-compatible Markdown task-discovery performance and reliability patch. It removes a redundant parser call for every source line while preserving the complete released feature set.

## Changes

- `parseOpenTasks` now classifies each Markdown line once with task-and-bullet awareness.
- That single result continues to maintain the hierarchy stack and now also supplies the emitted task or bullet record.
- Task-only reads explicitly skip ordinary bullet results after hierarchy processing, preserving the released parent relationships without reparsing.
- Completion mapping and filtering, task/bullet inclusion, source line and internal identity, indentation and parent lines, text cleanup, inline fields, preview limits, overflow counts, creation, drag/drop, settings, commands, and persisted data are unchanged.
- No fallback, public API, compatibility alias, supported integration path, or user-facing feature was removed.

## Before/after evidence

The release comparator compiles and executes the real private `KanbanView.parseOpenTasks` implementation from exact public `0.1.6` and the candidate. The baseline `KanbanView.ts` is SHA-256 pinned to `390c34d0dfd7c6226a27f799f644f39fa0b6f5158d0b8543f596627e3ff774d9`.

- The untouched `0.1.6` baseline passed all 76 declared checks and its contained production build before editing.
- A focused regression first failed against released behavior with 10 parser calls for five source lines, then passed with exactly five after the change. It also asserts exact task-only and bullet-inclusive output, nested parent lines, done-task filtering, and hierarchy reset.
- 100,000 deterministic randomized CRLF lines covered task markers, custom checkbox states, ordinary and ordered bullets, spaces and tabs, prose and headings, inline fields, tags, block IDs, comments, Unicode, malformed checkbox-like text, and empty lines.
- Eight combinations of task/bullet inclusion, completed-item inclusion, status mappings, and bounded/unbounded limits produced 800,000 zero-difference comparisons. The parity digest was `ee278c146d7a1f0f1cf4bc630ab5c6f5261ee1686a6c8901e3c5ec36ab0fa0b2`.
- Parity-work classifications fell exactly from 1,600,000 to 800,000.
- In the 25,000-line benchmark, 21 interleaved samples of five parses each reduced classifications from 5,250,000 to 2,625,000. Median time fell from 208.87 ms to 198.28 ms (5.07%), and p95 fell from 210.80 ms to 201.44 ms (4.44%).
- An independent adversarial audit added 133,360 real-method comparisons across 30,418 documents and 806,652 source lines with zero mismatches; its separate 41-round benchmark improved median time 4.52% and p95 5.52%.
- Runtime source changed by three additions and four deletions, and the production bundle decreased from 228,691 to 228,688 bytes.

The comparator hard-fails if the baseline source hash changes, any emitted result differs, released and candidate call counts are not exactly two and one per source line respectively, classifications are not halved, or controlled median/p95 timing fails to improve.

## Compatibility and limitations

- Minimum supported Obsidian version remains `1.10.0`.
- No settings or data migration is required.
- The only theoretical behavior difference requires unsupported runtime monkeypatching of the private line parser so it returns different values on two successive calls for the same line. Removing that dependence makes the normal typed path more deterministic.
- This patch does not alter task creation or target resolution. Root task creation still requires an explicit target and never gains an implicit fallback note.
