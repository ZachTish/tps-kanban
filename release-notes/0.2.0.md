# TPS Kanban 0.2.0

## Intent

Make Kanban's synthesized task and bullet rows first-class Base records without turning Kanban into a second formula engine or relying on private plugin discovery, partial indexes, guessed Base ownership, or writable fallbacks for computed fields.

## User-visible changes

- Top-level Base formulas now drive selected task/bullet card fields, lane grouping, filters, sorting, search, and style rules.
- Formula contexts expose row-first inline fields plus `row`, `note`, `file`, `this`, `task`, one-based `line`, and stable render-time `now`.
- Boolean formula values render as native disabled checkboxes instead of literal `true`/`false` text.
- Bare `kind` is additive. Checkbox rows and notes with frontmatter `kind: task` both satisfy `kind == task`; explicit line kinds such as `project` supplement rather than replace the structural task/bullet identity. `itemKind` and `itemType` remain structural-only.
- Formula-backed lanes are visibly read-only. Add, rename, and drag mutations are disabled because a computed result has no supported writable backing property.
- Global task/bullet source discovery uses Entity Index v3 revisions and exact structural queries. Additions, removals, replacements, transient failures, and event storms are handled atomically with serialized reads and bounded retries.
- Task-line editing, context menus, checkbox/status mapping, formulas, line metadata, and entity discovery now use exact public GCM capabilities and recover across either load order, replacement, unload, and reload.

## Reliability and performance

- Kanban accepts only the complete GCM formula v1 contract, including provider-owned formula-reference detection. The copied formula-reference scanner has been removed. Detection is tri-state: a thrown or invalid provider result rejects the synthetic row and remains fail-closed under `not`, `or`, and compound/computed references.
- Formula and line records fail closed when an evaluated expression, typed conversion, operator, Base authority, API version, or canonical line parse is unavailable. No same-named note property, regex metadata parser, temporary note, private Bases evaluator, `eval`, or `Function` fallback is used.
- Direct Base tabs resolve their owning file from the containing workspace leaf. Embedded views accept only one authoritative matching Base definition; ambiguous matches disable formula/filter evaluation.
- Entity Index `queryAsync` owns readiness, so Kanban no longer performs a redundant `ensureReady` call before every source query.
- Formula definitions compile once per authoritative Base revision, row sessions memoize dependent formulas, immutable file context is reused during a render, and diagnostics are bounded and deduplicated.

## Compatibility and migration

- Existing settings, commands, task lines, notes, Base definitions, lane order, and creation defaults need no migration.
- Minimum supported Obsidian remains 1.10.0.
- TPS Global Context Menu 1.14.0 or newer is required for synthesized formula, canonical line-metadata, Entity Index v3, and exact task-interaction capabilities. Ordinary native note rows and boards without these synthetic features retain their existing standalone behavior.
- Native note formulas remain evaluated by Obsidian. Kanban evaluates only synthesized task and bullet rows through GCM's supported API.

## Validation

- All 94 release-declared tests pass with zero skips: 3 shared-contract checks, 5 Base-filter composition checks, 82 focused Kanban checks, and 4 settings-contract checks.
- The focused suite covers additive note/task/bullet Kind identity, exact formula/line/entity/task capabilities, typed formula fields, filters, tri-state formula-reference failures under `not`/`or`, grouping, sort, search, styles, native boolean controls, read-only formula lanes, exact Base authority, lifecycle recovery, Entity Index revision ownership, serialized event storms, and bounded failures.
- TypeScript and the mandatory separate production-mode build pass from the isolated 0.1.8-based release worktree and deploy the exact candidate only to the verified test runtime.
- After `Reload app without saving` in Obsidian 1.12.7, a temporary formula Base settles atomically to two checkbox tasks in computed `todo` and `working` lanes. Formula booleans render as unchecked/checked native controls, numeric estimates render as 30/45, and the undated completed task remains excluded. Formula lanes show their read-only state; no add, edit, checkbox, drag, or outbound action is invoked.
- The temporary Base was moved directly to `_archive`. Runtime `data.json` remains SHA-256 `63aa45e09d7284b5357f879491c6cb9a6ccc2330a00e4e6f035b8f27359c29f3`; production was not accessed.

## Known limitations

- Computed formula fields are read-only and cannot be a creation or drag/drop mutation target.
- If GCM is disabled or incompatible, formula-bearing synthetic rows and global Entity Index discovery fail closed until the exact public capabilities are available again.
- Embedded formula/filter ownership requires one unambiguous matching Base block; Kanban intentionally does not guess between multiple candidates.
