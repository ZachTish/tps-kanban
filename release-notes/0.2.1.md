# TPS Kanban 0.2.1

## Intent

Prevent protected Markdown examples from becoming task or bullet cards, while keeping one supported GCM-owned parser boundary for discovery and metadata.

## Changes

- Synthesized task/bullet discovery now consumes only physical lines admitted by GCM `lineMetadata.scanDocument`.
- YAML frontmatter plus fenced, indented, HTML, and comment blocks cannot become cards. Valid nested tasks retain physical line IDs, hierarchy, filters, formulas, and editing routes.
- Removed raw-document discovery and copied inline-metadata fallback paths. GCM's canonical `parseLine` result is authoritative.
- Missing, incompatible, throwing, malformed-coordinate, or invalid parse results fail synthesized discovery closed with bounded diagnostics.

## Compatibility and migration

- Backward-compatible patch; no settings, Base, note, task, lane, or stored-data migration.
- Minimum supported Obsidian remains 1.10.0.
- TPS Global Context Menu 1.17.0 must be installed first for synthesized task/bullet cards. An older or disabled GCM intentionally suppresses those rows rather than parsing quarantined text.

## Validation

- Focused Kanban coverage verifies protected-block exclusion, legitimate nested identity, hierarchy boundaries, exact scan coordinates, missing/incompatible contracts, scanner failures, and invalid metadata results.
- The complete declared Kanban suite passes 104/104 tests, followed by TypeScript and a mandatory separate production-mode build in the isolated test vault.
- Test-vault reload and live Kanban QA confirm eligible cards remain visible and quarantined examples remain absent. Runtime-owned state remains unchanged; production is not accessed.

## Known limitations

- Synthesized task/bullet cards depend on the coordinated GCM scanner. Native note rows remain independent.
- Formula-backed fields and lanes remain read-only as documented in 0.2.0.
